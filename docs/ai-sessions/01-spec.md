  A. Listing: filter, sort, pagination

  1. City filter:
     - a) Case-insensitive exact match on the trimmed value (recommended)
     - b) Case-insensitive "contains"
     - c) Exact match, case-sensitive
  2. Combining filters: City, zip and state are combined with AND, and each
     field takes one value (recommended). The alternative is letting each field
     take a list of values, e.g. state: [AZ, CA].
  3. Sorting by creation date:
     - a) One argument sortOrder: SortOrder = DESC, newest first; ties broken by
       id (recommended)
     - b) A general orderBy: { field: CREATED_AT, direction } input that can
       take more fields later
  4. Pagination:
     - a) None
     - b) Offset pagination (limit/offset) returning { items, totalCount }, 
       default limit 20, max 100 (recommended)
     - c) Cursor-based pagination in the Relay style (edges, pageInfo)

  B. Identity, details, delete

  5. ID format: UUID generated by the database, exposed as GraphQL ID!
     (recommended). The alternative is cuid.
  6. Property that doesn't exist:
     - a) property(id) returns null, and deleting a missing id returns a 
       NOT_FOUND error (recommended)
     - b) Both return NOT_FOUND
  7. Delete: Hard delete. deleteProperty(id: ID!): ID! returns the deleted id,
     which is enough to remove the record from Apollo's cache (recommended).
     Alternatives: return the deleted Property object, or use a soft delete with
     a deletedAt column.
  8. Updating a property: Out of scope, since no user story asks for it
     (recommended). So there is no updatedAt field either.
  9. Duplicate addresses:
     - a) Reject them with an ALREADY_EXISTS error. A unique constraint covers
       street + city + state + zip after normalization. The duplicate check runs
       before calling Weatherstack, which also saves API quota (recommended).
     - b) Allow duplicates

  C. Input validation

  10. USState enum:
      - a) The 50 states plus DC (recommended)
      - b) Also include the territories (PR, GU, VI, AS, MP)
  11. Normalization and limits: Trim whitespace, collapse repeated spaces and
      keep the original casing. Street is 1–200 characters and city is 1–100.
      Zip code is a string, so leading zeros survive (e.g. 02134) (recommended).

  D. Weatherstack

  12. What we send as query:
      - a) "{zipCode}". Weatherstack treats a 5-digit value as a US ZIP
        (recommended).
      - b) "{city}, {state}, United States"
      - c) The full address: "{street}, {city}, {state} {zip}"

      In every case, Weatherstack returns the coordinates of the place it
      matched, not of the exact street address. The spec will say this
      explicitly.
  13. Checking the match: Reject the result if location.country isn't the United

      - b) f (Fahrenheit), because the properties are in the US

        are required fields (recommended)
      - b) Save the property with null weather fields and flag it
  16. Timeout and retries: A 5-second timeout using AbortSignal.timeout and no

  Decisions I made that you didn't explicitly ask for:
  - Shared validation package. I added packages/validation, which holds the zod
    schemas and the US_STATES list for both the API and the web form. That keeps
    the form's checks identical to the API's. If you want only two apps, it's
    easy to fold back into apps/api and copy the rules to the web app.
  - Duplicate check via a stored key. Prisma's schema can't declare a
    case-insensitive unique index. So each row stores an addressKey column
    (street, city, state and zip, lowercased) and the unique constraint is on
    that. A pure function computes it and has its own tests.
  - City characters restricted. City may contain only letters, spaces and ., ',
    -. Prisma's case-insensitive equality becomes a SQL ILIKE, where % and _ act
    as wildcards. Ruling those characters out means the "exact match" rule
    holds without any escaping code.
  - Errors mapped in one place. Services throw plain error classes, and a single
    function passed to Yoga turns them into GraphQL errors with codes.
    Resolvers never catch errors.
  - Codegen setup. The API uses the Codegen server preset, and the web app uses
    the client preset (typed documents passed to Apollo's useQuery). The Codegen
    docs now recommend the client preset over the older hooks plugin, which is
    a slight change from how CLAUDE.md words it ("generated typed hooks").
  - Fake provider switch. WEATHER_PROVIDER=fake selects the fake weather
    provider at runtime. The Playwright flow needs this, and it also lets
    reviewers try the app without an API key.

  Checked with context7: Yoga's maskedErrors.maskError and testing through
  yoga.fetch, the Codegen server and client presets, and the Prisma 7 setup (the
  prisma-client generator with a required output, prisma.config.ts, the
  @prisma/adapter-pg driver). The spec says which parts were checked. One thing
  is flagged to re-check during implementation rather than assumed: the import
  path for Apollo Client 4's React hooks.

  Weatherstack payload not confirmed live: the response shape in §4.3 comes from
