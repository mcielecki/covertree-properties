  Plan: Milestone 8, E2E smoke flow

  Design

  - Isolated ports. Playwright starts its own api on :4100 and web on :5174
    (vite --strictPort), with reuseExistingServer: false. Without this, a
    running pnpm dev (api :4000 on the dev database) could be reused, and the
    test would write into dev data.
  - api webServer: pnpm --filter @covertree/api exec tsx src/main.ts with
    DATABASE_URL=<e2e url>, WEATHER_PROVIDER=fake, PORT=4100 and
    CORS_ORIGIN=http://localhost:5174. Readiness is checked via GET /health.
    Variables set here win over the root .env, because main.ts already works
    that way.
  - web webServer: Vite dev server with
    VITE_GRAPHQL_URL=http://localhost:4100/graphql.
  - E2E database: E2E_DATABASE_URL comes from env, else the root .env, else the
    default postgresql://covertree:covertree@localhost:5432/covertree_e2e. A
    guard refuses any database whose name doesn't end in _e2e, the same idea as
    the _test guard. It never reads DATABASE_URL.
  - globalSetup: runs prisma migrate deploy and then truncates via prisma db 
    execute --stdin (TRUNCATE TABLE properties). Both go through the api's
    Prisma CLI with DATABASE_URL set only for that child process. This means web
    doesn't need a pg dependency. I'll check with context7 how db execute picks
    its URL in Prisma 7, and whether Playwright starts globalSetup before or
    after webServer.
  - TypeScript and lint: a separate e2e/tsconfig.json with Node types, so
    process and node:* types don't leak into browser code. The web typecheck
    script covers both configs. ESLint's projectService must see
    playwright.config.ts too, and I'll wire that in.

  What was built

  - apps/web/e2e/property-smoke.spec.ts: the flow from SPEC §7.4. It uses only
    role- and label-based locators and covers AC-W.1, W.2, W.4, W.6 and AC-3.1,
    3.6, 5.1.
    a. Create a property; the app opens its details page.
    b. It is the first row on the list.
    c. The city filter fountain hills still shows it.
    d. Adding state CA hides it.
    e. Clear the filters, delete it through the confirmation dialog, and the
       list is empty without a reload.
  - apps/web/playwright.config.ts: Playwright starts its own api on :4100 (fake
    weather provider, covertree_e2e database) and Vite on :5174. It refuses to
    reuse a server that is already running. This way a running pnpm dev, which
    uses the dev database, can never be picked up.
  - e2e/e2e-database.ts + e2e/e2e-database.test.ts (written test-first, 10
    tests, part of pnpm test): the database URL comes from E2E_DATABASE_URL,
    else the root .env, else the compose default. It refuses any database whose
    name doesn't end in _e2e, never reads DATABASE_URL, and doesn't leak the
    password in errors.
  - e2e/global-setup.ts: runs the api's Prisma CLI to migrate the database and
    then empty it. No new database dependency in web.
  - e2e/tsconfig.json: gives the e2e files Node types without adding them to the
    browser code.
  - Wiring:
    - test:e2e script, and typecheck now covers the e2e tsconfig too.
    - Vitest also picks up e2e/**/*.test.ts.
    - An ESLint setting so the linter can type-check playwright.config.ts.
    - .gitignore covers the Playwright report folders; E2E_DATABASE_URL added to
      .env.example.
    - @playwright/test 1.63.0 added.
